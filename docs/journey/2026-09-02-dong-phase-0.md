# 02/09/2026 — Đóng Phase 0: từ luật prototype tới contract kiểm chứng được

## Mục tiêu của Phase 0

Phase 0 dùng prototype local để loại các mâu thuẫn luật/state nghiêm trọng trước khi dựng multiplayer. Điểm thoát không phải “game đã production-ready”, mà là core flow có thể chạy hết trận, deterministic, reject action sai atomically, replay được và không gửi nhầm hidden information qua transcript prototype.

## Phạm vi đã hoàn tất

| Mốc | Outcome |
|---|---|
| P0.1 | Đồng bộ Hội đồng, reveal đêm, Tiên tri và Kẻ Thế Mạng với rule đã chốt |
| P0.2 | Thanh trừng V6–V9, ownership ổn định và chặn deadlock Swap |
| P0.3 | Exhausted voter, reaction window và simultaneous batch resolution |
| P0.4 | Ranh giới public/private cho Night, Guard và Seer |
| P0.5 | Final Duel, match result, reveal cuối trận và rematch local |
| P0.6 | Seeded full-match simulator + invariant state |
| P0.7 | Invalid-action fuzz + atomic rejection |
| P0.8 | Authoritative action replay + deterministic state digest |
| P0.9 | Recipient action/digest projection deny-by-default |
| P0.10 | Typed public outcome schema + recipient outcome delta audit |

## Exit evidence

- Engine/simulator regression cuối: **54/54 automated test pass**.
- P0.6 audit: 5.000/5.000 match kết thúc trong transition guard.
- P0.7 audit: 76.991 invalid action bị reject atomically.
- P0.8 audit: 15.665 replay event không divergence.
- P0.9 audit: 11.190 hidden action projection, leak 0.
- P0.10 audit: 15.306 transition, 11.125 typed outcome và 10.995 hidden action, schema/recipient leak 0.
- Browser evidence đã có cho privacy Night, Purge V6–V9, Final Duel/result/rematch ở các mốc trước; P0.10 không đổi UI nên không tạo browser claim mới.

## Quyết định đóng phase

- Phase 0 đóng tại P0.10. Không tự mở P0.11 trừ khi có regression chặn entry vào P1.
- Prototype engine là executable spec cho P1, không phải server production.
- Authoritative replay ở server/internal; client nhận projected command envelope, đúng private view và typed public outcome.
- Log text chỉ phục vụ presentation/debug, không là protocol.

## Những gì chưa được chứng minh

- Hai client thật, serialization, packet reorder/duplicate, latency, reconnect/resume và command idempotency.
- Security boundary của server production, persistence và migration/versioning event.
- Human comprehension, match duration, balance, first-player advantage và độ vui.
- Một số priority edge case design vẫn ở tracker; fuzz pass không tự biến chúng thành quyết định game design.

## Entry vào Phase 1

Phase 1 bắt đầu từ authoritative room contract: `commandId`, `stateVersion`, retry/idempotency, event persistence và transport cho hai recipient. Sau đó mới kiểm hai browser join room, desync/reconnect và nối UI vào typed outcome consumer.
